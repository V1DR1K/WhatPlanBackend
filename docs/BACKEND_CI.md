# Backend CI status

The `Backend CI` workflow runs `mvn verify` with Java 21 for pushes and pull requests targeting `CoupleExpantion`. The GitHub-hosted Linux runner supplies Docker to the repository's PostgreSQL and Redis Testcontainers suites. It also runs a pinned OSV dependency scan and a pinned Gitleaks history scan, generates a CycloneDX SBOM, and retains Maven test reports plus the SBOM for 14 days. The workflow does not deploy. The `security-events: write` permission is restricted to the workflow's dependency-scanning purpose; repository contents are read-only and checkout credentials are not persisted.

This is a stronger C28 baseline, not a completed release gate. The PostgreSQL Testcontainers migration suite explicitly calls Flyway `validate()` after migrating. `CoupleHttpIsolationIntegrationTest` exercises the production JWT/filter/controller/data-source path against a restricted PostgreSQL runtime role and Redis, checking A/B place reads and writes, forged `X-Couple-Id`, shared-member writes, personal reviews, photos, an administrator, and a user without membership. Production code and all test sources compile with Java 21; 140 non-container tests pass. The three Testcontainers suites, including the new HTTP test, have not run: Docker is unavailable locally, while the configured VPS already hosts WhatPlan and other production services, so it has not been used to launch test containers. The remaining HTTP matrix for private modules, branch-protection enforcement, scan finding triage, and a successful GitHub-hosted run are still unverified. No successful CI run is claimed until those checks execute.
